# Подключение своего домена (например family-budget.online)

Заметка на будущее. Архитектура к своему домену готова — код менять почти не нужно,
всё держится на настройке DNS, Amvera и Google Console.

## Стоит помнить перед покупкой

- **Цена продления.** Первый год часто промо (напр. 249 ₽), а `.online` — дорогой на
  продление TLD (обычно пара тысяч ₽/год). Перед покупкой посмотреть цену именно
  **продления**, а не только первого года. Альтернатива — `.ru/.рф` (продление дешевле,
  но нужны паспортные данные).
- **Не брать допуслуги** в заказе: «Домен плюс» (690 ₽/мес), Premium DNS, почта и т.п.
  не нужны. Итог должен остаться равным цене самого домена.
- **Выбрать домен один раз и сразу раздавать его знакомым.** Переезд между доменами
  потом = лишняя возня (см. про E2E-ключ ниже).

## Что уже готово в коде (менять не надо)

- **Веб:** `public/manifest.json` → `start_url: "/"` (относительный). Авторизация — JWT в
  заголовке `Authorization: Bearer`, не cookie, к домену не привязана. Открывается по
  любому адресу как есть.
- **Приложение:** адрес сервера НЕ захардкожен. Пользователь вводит его на экране входа
  («Введите адрес вашего сервера»), хранится в SecureStore (`server_url`,
  `android/src/api/client.ts`). Новым пользователям даём новый домен — вводят, работает.
- **OAuth-редирект:** сервер строит `redirect_uri` динамически из `req.headers.host`
  (`app.set('trust proxy', true)` в `src/server.js`). Домен подставляется автоматически.

## Чек-лист настройки

### 1. Amvera — привязать домен + TLS
- В панели проекта Amvera добавить кастомный домен `family-budget.online`.
- Включить/дождаться выпуска TLS-сертификата (Let's Encrypt, у Amvera автоматически).
- Amvera выдаст целевую DNS-запись (CNAME на их endpoint или A на IP) — записать её.

### 2. Reg.ru (DNS) — направить домен на Amvera
- В управлении DNS домена прописать запись из шага 1
  (CNAME для поддомена / A-запись для корня — как скажет Amvera).
- Подождать распространения DNS (от минут до нескольких часов).
- Проверить: `https://family-budget.online` открывает веб-версию по HTTPS.

### 3. Google Cloud Console — единственный неочевидный шаг
Иначе вход через Google на новом домене упадёт с `redirect_uri_mismatch`.
В настройках OAuth 2.0 Client ID добавить:
- **Authorized JavaScript origins:** `https://family-budget.online`
- **Authorized redirect URIs:** `https://family-budget.online/auth/google/mobile/callback`

(Старые записи Amvera-домена не удалять — пусть оба домена работают параллельно.)

### 4. Проверка
- Веб: вход через Google + вход по логину/паролю.
- Приложение: на новом устройстве ввести `https://family-budget.online` как адрес
  сервера, войти.
- Старые установки со старым Amvera-адресом должны продолжать работать (не отключать
  старый поддомен, пока все не переехали).

## Важные нюансы

- **Один сервер и одна БД.** Домен — просто другая «дверь» к тому же бэкенду. Семьи,
  аккаунты, E2E-ключи — общие. Никакой миграции данных. Заход по amvera-адресу и по
  своему домену — один и тот же аккаунт.
- **E2E-ключ в вебе привязан к домену (origin).** Ключ шифрования хранится в
  `localStorage` конкретного домена (`family_e2e_key` в `public/e2e.js`). При переезде
  на новый домен ключ НЕ переедет автоматически — нужно один раз ввести его заново
  на новом домене: Настройки → 🔒 Приватность → «📥 Ввести ключ с другого устройства».
  Поэтому финальный домен лучше выбрать сразу.
- **PWA/Service Worker тоже привязаны к origin.** Если кто-то добавил на домашний экран
  старый адрес, на новом домене PWA переустановится заново (это нормально).
